# FPS 输入系统与角色移动

> 范围：输入映射、角色构成与插槽、移动状态机、瞄准与灵敏度。**不含**开火（见 `fps-02`）与受伤（见 `fps-03`）。

## 结论

这条线的角色控制是「**纯蓝图 + 枚举驱动的状态机**」，不是 GAS 的 `AbilitySystemComponent`，也没有 C++。演进顺序为：

1. 先把 IA/IMC 与角色骨骼插槽搭起来（能走能看）；
2. 再用枚举做移动状态切换（Walk / Run / Aim 等），动画蓝图按枚举取对应动画；
3. 最后把移动手感改成「三角洲」式的重量感（加速度、制动、脚步节奏），并补上瞄准与灵敏度。

## 反例与坑

**坑 1：`IA_*` 的默认累加行为导致 AD / WS 同时按不静止**

DEVLOG 已记录完整链路（症状 → 根因 → 修法），这里只保留结论：

> 症状：设置移动的 InputAction，默认参数导致同时按住AD或者WS不能静止。

根因是输入累加策略（`AccumulationBehavior`）的默认值。修法见 DEVLOG 原文中的源码注释引用。

**坑 2：资产不能随意改父目录**

> UE 引擎会对每个资产的管理可以理解为以 Content 开始的绝对路径……不能改变。

这条对 FPS 线尤其重要：`Content/FPS/` 下的 `IA_*`、动画蓝图、角色之间存在大量互相引用，**任何目录调整都必须走「迁移」而非资源管理器复制**。
