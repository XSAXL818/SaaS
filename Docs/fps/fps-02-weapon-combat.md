# FPS 武器与开火

> 范围：武器蓝图、开火流程、表现层（枪口火焰 / 弹壳 / 后坐力 / 弹道 / 弹孔 / 音效）、换弹、枪械 UI。**不含**伤害结算与死亡（见 `fps-03`）。

## 结论

开火是这条线里迭代次数最多的系统（25 次提交中占 12 次），演进路径可以清楚分为三段：

| 阶段 | 提交 | 做了什么 |
|---|---|---|
| **1. 能打出去** | `70a1572` → `b85549f` → `3deb846` | 开火蒙太奇动画 → 音效改用 MetaSound → 优化开火逻辑 |
| **2. 打出去有反馈** | `8f649b5` → `310a97a` → `879cb34` → `89a60c3` → `b23505e` | 枪口火焰 → 弹壳生成 → 后坐力 → 击中特效与音效 → 弹孔痕迹 |
| **3. 手感与弹药** | `98cf9e1` → `8b1bb41` → `912564b` → `074fcfe` → `6b25510` | 换弹系统 → 后退行走时上移弹道 → 修换弹 bug → 修 run→walk 开火动画过渡 → 枪械 UI |

**规律**：先做「动作 + 声音」，再加「视觉反馈」，最后做「数值与状态」（弹药、UI）。这个顺序避免了在弹道未稳定时反复改 UI。

## 反例与坑

**坑 1：动画过渡时间会拖慢开火响应（`074fcfe`）**

从 Run 切到 Walk 时，「立刻开火」要等动画过渡播完才生效，观感是「按了扳机没反应」。这不是音效或特效的延迟，而是**动画状态机过渡规则**的问题——排查时容易误判到开火逻辑上。

**坑 2：换弹 bug（`912564b`）**

提交只说「修复换弹 bug」，具体成因**未记录**。这类「修了但没写清楚」的提交，以后重犯的概率很高——已列入待补清单。
